## msgSecCheck 真正跑通（关键 bug 修复）
- **发现**：内容安全链路早就写好了，但微信那段一直是坏的。`msg_sec_check` POST 返回
  **HTTP 412 Precondition Failed（无响应体）**，被 fail-open 吞成「放行」，
  所以「审核配好了却什么都没拦住」，日志只有一行 warn
- **根因（实测三种写法）**：微信拒绝 **chunked** 的 POST
  - `HttpURLConnection` + `setFixedLengthStreamingMode` → 200
  - `HttpURLConnection` + `setChunkedStreamingMode` → **412**
  - JDK `HttpClient` + `BodyPublishers.ofString` → 200
  Spring 的 `SimpleClientHttpRequestFactory`（默认流式）和 `JdkClientHttpRequestFactory`
  （自带 OutputStreamBodyPublisher）**都会退化成 chunked** → 换工厂无效（已验证）
- **修法**：`WxSecurityService` 里 token / msg_sec_check / media_check_async 三个调用
  全部改用私有 `HttpClient`（HTTP/1.1、connect 5s、read 8s、Content-Length 定长）；
  `AuthConfig` 的 RestTemplate 还原，仅用于 GET（code2Session / 逆地理），并加注释警告别再发 POST
- **新增** `GET /internal/security/selfcheck`（`WxSecurityService#diagnose`）：
  真拉 token + 真发一次探测，返回 `token{ok,errcode,hint}` / `probe{suggest,label}` /
  `hints[]` / `ready`；不写 `t_content_audit`，可反复调；`tokenHint()` 把
  40013/40125/40164/45009 翻成中文建议
- **实测**（临时实例 18101，`--campus.wx.sec-check.enabled=true`，register-enabled=false）：
  selfcheck → ready=true, probe risky label=20006；
  `/msg-check` 违规文本 → `{"code":400}`；正常文本 → `code:0`；
  `t_content_audit` 落一条 source=2 REJECT（已删测试行）
- **注意**：`suggest` 不是确定性函数，同一条文本今天可能 risky 明天 pass，
  所以自检只判「接口通不通」，不拿单次 pass 当配置错误
- 文档 `docs/content-security.md` 补 §5.3 自检 / §5.4 实测 curl / §5.5 错误码表 /
  §5.1 两种配置方式 + 必须重启 / §6 传达层坑；`content-security-check.js` 35/35 通过
- **待用户操作**：8101 上跑的还是旧包，需要重启 campus-auth 才吃到修复
