## msgSecCheck 真正跑通（关键 bug 修复）
- **发现**：内容安全链路早就写好了，但微信那段一直是坏的。`msg_sec_check` POST 返回
  **HTTP 412 Precondition Failed（无响应体）**，被 fail-open 吞成「放行」，
  所以「审核配好了却什么都没拦住」，日志只有一行 warn
- **根因（实测三种写法）**：微信拒绝 **chunked** 的 POST
  - `HttpURLConnection` + `setFixedLengthStreamingMode` → 200
  - `HttpURLConnection` + `setChunkedStreamingMode` → **412**
  - JDK `HttpClient` + `BodyPublishers.ofString` → 200
  Spring 的 `SimpleClientHttpRequestFactory`（默认流式）和 `JdkClientHttpRequestFactory`
  （自带 OutputStreamBodyPublisher）**都会退化成 chunked** → 换工厂无效（已验证）
- **修法**：`WxSecurityService` 里 token / msg_sec_check / media_check_async 三个调用
  全部改用私有 `HttpClient`（HTTP/1.1、connect 5s、read 8s、Content-Length 定长）；
  `AuthConfig` 的 RestTemplate 还原，仅用于 GET（code2Session / 逆地理），并加注释警告别再发 POST
- **新增** `GET /internal/security/selfcheck`（`WxSecurityService#diagnose`）：
  真拉 token + 真发一次探测，返回 `token{ok,errcode,hint}` / `probe{suggest,label}` /
  `hints[]` / `ready`；不写 `t_content_audit`，可反复调；`tokenHint()` 把
  40013/40125/40164/45009 翻成中文建议
- **实测**（临时实例 18101，`--campus.wx.sec-check.enabled=true`，register-enabled=false）：
  selfcheck → ready=true, probe risky label=20006；
  `/msg-check` 违规文本 → `{"code":400}`；正常文本 → `code:0`；
  `t_content_audit` 落一条 source=2 REJECT（已删测试行）
- **注意**：`suggest` 不是确定性函数，同一条文本今天可能 risky 明天 pass，
  所以自检只判「接口通不通」，不拿单次 pass 当配置错误
- 文档 `docs/content-security.md` 补 §5.3 自检 / §5.4 实测 curl / §5.5 错误码表 /
  §5.1 两种配置方式 + 必须重启 / §6 传达层坑；`content-security-check.js` 35/35 通过

## 并发 / Redis / MQ 全量审计（docs/CONCURRENCY-AUDIT.md）
- **总判断**：单实例 + 无缓存 + 无 MQ 的纯直连架构。**Redis 容器在 docker-compose 里跑着但代码 0 处使用**，
  MQ 完全没有；全仓 16 处 `CompletableFuture.runAsync` 用 commonPool 硬扛异步通知
- **最狠的雷（1 分钟可修）**：只有 campus-message 配了 Feign 超时（3s/5s），
  **auth/user/goods/post/wall/admin 六个服务全用默认 connect 10s / read 60s**
  → 下游一停顿即 60s 不还连接，Hikari 10 连接打满 → 该服务全体接口超时（典型雪崩链）
- **吞吐天花板**：Hikari 每服务 10 连接 + 事务内同步调微信 `msg_sec_check`（超时 8s）
  → 审核 200ms 时 ~40TPS，审核 2s 时 ~4.8TPS，审核 8s 时 **~1.2TPS 且连接池占满**
- **已修 3 个确定性一致性 bug**（编译通过）：
  1. 三处 `toggleLike`（goods/post/wall）`deleteById` 不判影响行数就 `incrLike(-1)` → 并发双取消计数永久漂移；
     `greatest` 只防负数防不了漂移。参照 `FollowService#unfollow` 的正确写法补 `if (deleteById>0)`；
     并补 `uk_target_user` 的 `DuplicateKeyException` 兜底（并发双点赞原来会 500）
  2. `UserService#loginOrCreate` 并发建号撞 `uk_platform_openid` → 冷启动双 ensureLogin 必偶发 500；
     catch 后重新 select 返回
- **待决策（未改）**：`changeStatus` 全量覆盖无状态机（已售出可能被改回在售）；`createOrder` 无 CAS；
  所有 Feign/微信调用在 `@Transactional` 内（长事务持锁）
- **推 Redis 的 6 处**：微信 access_token 集中（多实例互相踢 → 审核 fail-open 静默放行，最紧急）/
  未读角标（tab 每 show 都拉，含跨表 JOIN count）/ 运营位+字典缓存 / 详情页 view_count 热行 /
  写接口限流（网关零限流）/ JWT 吊销版本号
- **推 MQ 的 3 处**：通知系统（丢失+事务前发送+无幂等，配本地消息表 t_outbox）/
  微信审核移出事务（先发后审）/ 计数回写；选型建议 RabbitMQ，别上 Kafka

## 安全加固（全量审计 + 修复，2026-10-26 凌晨）
> 完整报告：`docs/安全审计报告.md`。做了三件大事：身份链路、密钥、口令哈希，以及敏感字段加密。

- **身份链路**：C 端身份只认 JWT（`SecurityAutoConfig`），后台 `AdminAuthInterceptor` 必须 token 与 `X-Admin-Id` 一致且权限读 claim。
  实机复现过：直连 8102 带 `X-User-Id` 能拿人资料、直连 8107 带 `X-Admin-*` 直接是超管 → 现均 401
- **密钥**：`SecretStore`/`SecretResolver`（env → `~/.campus-secrets/<name>` → 随机生成）；yml 里不再有 secret 字面量；
  `CAMPUS_SECRET_STRICT=true` 缺密钥即启动失败。令牌加 `iss/aud/typ`，C 端 72h
- **口令**：MD5(明文+固定盐) → BCrypt cost12；登录成功自动升级旧哈希（已实测 admin 变 `$2a$12$`、salt 清空）
- **字段加密**：`DataCipher`(AES-256-GCM, `enc:v1:` 前缀) + `EncryptedStringTypeHandler` + `SearchHash` 盲索引
  ⚠️ **实体必须 `@TableName(autoResultMap = true)`**，否则写入加密、读出来还是密文（踩过）
  ⚠️ 加密列不能 LIKE/等值 → 学号查重走 `student_no_hash`、后台手机号搜索走 `phone_hash`
  历史数据迁移：`CAMPUS_SECURITY_MIGRATE_PLAINTEXT=true` 启动一次（user + goods），注意是 `CAMPUS_SECURITY_` 前缀
- **网关**：CORS 白名单 + `allowCredentials=false`；`/actuator` 只放行 `/actuator/health`；新增 `SecurityHeadersFilter`
- **上传**：`FileMagic` 校验真实文件头（伪装 png 已实测拒绝）
- **数据库**：`sql/migration-20261026-security-hardening.sql`（扩列 + 盲索引 + campus_app 低权限账号脚本）；连接串 `MYSQL_SSL` 可配
- **构建坑**：IDE 的 redhat.java 会在后台把「未解析类型」编译进 `target/classes`，导致启动报
  `NoClassDefFoundError: LikeMapper`。已加 `.vscode/settings.json` 关 `java.autobuild.enabled`；遇此错先 `rm -rf target` 再 mvn
