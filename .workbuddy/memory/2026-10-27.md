## 修复：帖子/表白墙举报提交不了（用户报「没有权限」）

现象：点提交举报 → Console `TypeError: http is not a function`，旁边还挂着一个 401。
真因在前端，跟后端权限无关。

### 根因 1：`http` 不是函数
`miniprogram/utils/request.js` 的 `module.exports` 是**对象** `{ request, get, post, put, del }`，
但 `pages/report/report.js` 写成了 `http({ url, method, data })` → 同步抛 TypeError，请求根本没发出去。
全项目只有这一处这么写（其余 20+ 处都是 `http.get/post(...)`），所以只有举报挂。
修复：改 `http.post('/user/report', data, { loading: '提交中' })`。

### 根因 2：雪花 id 被 Number() 截断（顺手修）
原代码 `targetId: Number(d.targetId)`。19 位雪花 id > `Number.MAX_SAFE_INTEGER`：
`2114021598989209601 → 2114021598989209600`，工单会挂到错误内容上。改成 `String(...)`。

### 根因 3：意见反馈（FEEDBACK）提交必 500
`t_report_ticket.target_id` 建表是 `NOT NULL` 无默认值，而 FEEDBACK 没有举报对象（targetId=null）
→ `Field 'target_id' doesn't have a default value`。
之前从没暴露，因为请求压根没发出去。已放开空约束（MySQL 唯一索引允许多行 NULL，
所以每条反馈各自成单，不会被 `uk_target_reporter` 误合并——已实测两条反馈生成两张工单）。
迁移脚本 `backend/sql/migration-20261027-report-fix.sql`（幂等，需先 `USE guizhou_campus_fun`）。

## 推广功能（看激励视频广告换排序）—— 全量落地

需求：闲置商品能「推广」，看完一段广告就提升排序，看越多越靠前。
用户选定三件事：**微信激励视频广告** + **7 天线性衰减** + **覆盖闲置/帖子/表白墙**。

### 新增服务 campus-promote（8108，网关 `/api/promote/**`，全部要登录）
- `GET /promote/quota`（当前分 + 今日剩余次数 + 规则参数）
- `POST /promote/issue` 签一次性凭证（**此时不加分**）
- `POST /promote/complete` 看满时长后结算
- `POST /promote/cancel` 作废并释放配额
- `POST /promote/refresh` 手动触发衰减重算
- `PromoteDecayTask` 每 30 分钟重算「仍有推广记录」的内容并回写 `promote_score`

计费：`weight=100`，有效分 = `weight × 剩余时间 / 7天`，**线性衰减**（不是到期一刀切），
这样「刚推广」和「快过期」在排序上是连续差异，也不会到期瞬间整页重排。

### 防刷（关键，改动前先读）
「看完广告」只有客户端知道 → 必须两步走：签发凭证 → 结算。服务端校验：
1. `uk_nonce` 唯一键 + **带 `status=0` 的条件更新**（并发重复结算只有一次生效）
2. `now - issued_at >= PROMOTE_MIN_WATCH_SECONDS(15)` —— 跳过广告直接打接口被拒
3. 凭证 10 分钟过期，超时作废
4. 归属校验（Feign 查内容服务 owner）+ 每日上限（单条 5 / 单账号 20）
⚠️ 同步失败要**抛异常让事务回滚**（nonce 仍可用可重试），别 fail-open；
衰减任务兜底修复，最坏只是排序延迟一个周期。

## 首页顶部「地址选择」瘦身（布局优化，A+B 方案落地）

### 问题
`pages/index/index` 顶栏是一条 `position: sticky` 的 96rpx 白栏，里面只放一枚 `max-width:260rpx` 的学校胶囊，
右侧全空；叠加公告位 144rpx + Banner 316rpx，**顶部三块吃掉首屏约 1/3**，且 sticky 让这 96rpx 全程挂着。

### 改法（按需出现 + 瘦身）
- `index.wxml`：`.topbar` / `.school-pill` 整块删掉，换成一行 `.scope-bar`（`wx:if="{{scopeKind}}"`）。
  **默认不渲染**，只在两种状态出现：`onboard`（还没绑学校）/ `city`（已切到本市）。
  本市模式右侧带一枚 `catchtap="switchToSchool"` 的「切回本校」，不用再开弹层。
- `index.wxss`：`.scope-bar` 是纯文字行（无白底/边框/阴影、不 sticky、`padding-top:20rpx`），
  高度约 40~50rpx（原 96rpx）；字数溢出 `max-width:420rpx` 省略号。
  ⚠️ 删掉了 `position: sticky; top:0; z-index:30` —— 首页是纯信息流，不需要悬停顶栏。
- `index.js`：
  - `data.scopeKind`（`''` / `'onboard'` / `'city'`），由 `scopeKindOf(user, scope)` 统一判定：
    `!user || !user.schoolId → 'onboard'`，`scope==='city' → 'city'`，其余 `''`。
  - `applyUser` 里一起 setData；`syncMe` 两处未登录/404 兜底要同步补 `scopeKind:'onboard'`，
    否则清会话后顶部会空白（游客本来就需要「选学校」提示）。

## 修复：后台举报工单「操作」列空白（详情/处理按钮消失）

现象：`localhost:5173/report` 列表有数据、状态正常，但「操作」列整列空白；

- `router/index.js` 守卫：`loadInfo()` 先于 `loadMenus()`（info 失败不阻断菜单）。

## 选学校列表「没有按 IP 排序」（三处根因，2026-10-27）

## 「我的 → 购买意向」弹层被底栏盖住（显示不全）

- `pages/user/index.js`：`openOrders` 里 `toggleTabBar(true)`，`closeOrders` 里 `toggleTabBar(false)`。

## 修复：广告位 mine_banner 游客访问 401（网关子串误判）

体检 6 个广告位时发现：`GET /api/ads/mine_banner` 返回 **401 请先登录**（localhost 与线上域名一致复现），
其余 5 个都是 200。

根因：网关 `AuthGlobalFilter` 的私域判定写的是
`PRIVATE_HINTS.stream().noneMatch(path::contains)`，而 `PRIVATE_HINTS` 里是 `"/mine"`。
`/api/ads/mine_banner` 的路径**含有子串 `/mine`** → 被当成「我的」私域接口 → 游客 401。
登录用户能拿到（有 token），所以表现为「个人中心广告位只有登录后才显示、游客永远白块」，
两端都不报错，极难定位。

修法：改成**按路径段全等比较**
```java
private static final List<String> PRIVATE_SEGMENTS =
        List.of("mine", "orders", "favorite", "favorites");
private boolean hasPrivateSegment(String path) {
    for (String seg : path.split("/")) if (PRIVATE_SEGMENTS.contains(seg)) return true;
    return false;
}
```
（原来 `"/favorite"` 的子串写法顺手匹配到 `/favorites`，拆段后两个都要显式列出。）

## 修白屏：WXML 空态文案嵌套三目括号多一个（第六轮）

现象：`pages/goods/list` 编译报 `Bad value with message: error at token '}'`，
`/pages/goods/list.wxml:165:11`，整页白屏。

原因：上一轮把空态文案写成四层嵌套三目
`{{loadError ? 'A' : (mineMode ? 'B' : (favMode ? 'C' : (activeKeyword ? 'D' : 'E'))))}}`
——左括号 3 个、右括号 4 个，多一个 `)`。WXML 表达式解析器只在 `}}` 前报 token 错误，
不指向真实原因，很难肉眼定位。

改法：不再用嵌套三目，改成 `wx:if / wx:elif / wx:else` 链，文案各自一条 `<text>`，
`activeKeyword` 用原生 `{{}}` 插值。可读性也顺带好了。

- 先把 HTML 注释抹成等长空格（行号不变、注释里的 `{{}}` 不误判）
- 剔除单/双引号字符串字面量后核对 `()` `[]` 配平，报「文件 + 行号 + 哪种括号多几个」
- 已用注入法回归：塞回原坏表达式 → 报「pages/goods/list.wxml 第 171 行 → 出现多余的 )」，还原后通过

### 约定（写进档案第四节第 6 条）
**WXML 禁用三层以上嵌套三目**，分支超过 2 个一律 `wx:if/elif/else`。
