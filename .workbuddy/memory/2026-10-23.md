**现象**：QQ 开发者工具模拟器只有导航栏 + tabBar，页面内容空白；Console 报

post/publish、user/index、user/verify）。框架读不到页面配置对象 → pageConfig undefined → 白屏。
**这是静态语法检查发现不了的，只有结构校验能查。**

**修复**
- 补齐 10 个页面 json，全部显式写 `"usingComponents": {}`
- `app.json` 移除 `"style": "v2"`（QQ 不支持，属微信扩展字段）；不加全局 usingComponents（老基础库兼容性）
- 新增 `scripts/check-miniprogram.js`：校验页面 js/wxml/json 齐全、json 可解析且含 usingComponents、
  tabBar 页面已声明、页面 js 有 Page()、sitemap 存在、BOM 检查

**环境事实**：QQ 开发者工具已回写 `project.config.json`（加了 `qqappid: 1108100302`、`libVersion: 1.10.0`）。
基础库 1.10.0 偏老，对 CSS `gap`/`env()`、`wx:elif` 支持有限，真机可能布局异常。

**教训**：小程序页面 json 不是可选项（尤其 QQ），新建页面必须同时产出 4 个文件；加结构校验脚本兜底。

## 追加：诊断「请求 200 但页面报错」+ 补帖子编辑

**现象**：Network 里 6 个请求全 200，首页仍显示「加载失败」。响应体只有 431B/520B，明显不是列表数据。

**根因分析**：后端业务失败时返回 `{code:500/4xx, msg:"..."}` + HTTP 200。之前列表请求带 `{silent:true}`，
错误被静默吞掉，页面只设 `loadError=true`；且 `res[0].records` 在 data 为 null 时会抛 TypeError。

**修复**
- `request.js`：`console.error('[api] 业务失败', method, url, code, msg)`；响应体为字符串时兜底 JSON.parse；
  非法 JSON 单独分支
- 首页三个接口改为**分别 catch**（任一失败不影响其余渲染），把后端 msg 显示到页面：`errorMsg`
- 列表/详情页错误态统一展示 `errorMsg`
- 提示：此类「200 + code!=0」几乎都是后端侧问题（表不存在 / 库没切 / 服务连不上），
  排查入口就是 Console 的 `[api]` 日志

**补帖子编辑**
- 后端：`PostService.update()` + `PUT /posts/{id}`（`LambdaUpdateWrapper.set()` 显式赋值，支持清空图片）
- mock：`updatePost` + 路由
- 前端：`post/publish` 支持 `?id=` 编辑模式（预填 + PUT）；`post/detail` 右上 `···` → ActionSheet（编辑/删除）
- **修正**：`post/list` 的 goPublish 原用 `?id=` 传频道，与「编辑模式用 id」冲突 → 改为 `?channelId=`

**验证**：mock 自测 89/89（新增 6 条帖子编辑断言）、11 页结构通过、后端编译 EXIT=0。

**给用户的排查线索**：库名从 `campus_fun` 改成 `guizhou_campus_fun` 后，旧库数据不会自动过去；
若没重新导入 `schema.sql/data.sql`，接口会 500（表不存在）。

## 追加：定位到全站 400 的真正根因（-parameters）+ 地址配置集中

### 根因（实锤）
直接 `curl 127.0.0.1:8888/api/schools` 拿到：
`{"code":400,"msg":"Name for argument of type [java.lang.String] not specified ... '-parameters' flag"}`
→ **父 POM 手写、未继承 spring-boot-starter-parent，没开启 `-parameters`**，
Spring 6 无法反射方法参数名，所有带无名 `@RequestParam/@PathVariable` 的接口全 400。
（`/goods/categories`、`/auth/login`、`/user/me`、`/goods/favorites` 正常，正好都没这个特征 → 反证成立）

### 修复
- 父 `backend/pom.xml`：`maven-compiler-plugin` 加 `<parameters>true</parameters>` + `-parameters` compilerArg
- 批量给 6 个 controller 的 `@RequestParam/@PathVariable` 补显式 `name`（双保险，避免增量编译失效）
- 编译后 `javap -v` 验证 class 里有 `MethodParameters`（12 处）✓

### 新增自检脚本
`scripts/api-smoke-test.js`：Node 原生 http，依次打 12 个核心接口（公开→登录→登录后），
输出 ok/FAIL + 后端 msg + 常见原因对照。当前实测 8 个失败全部指向 -parameters。

### 地址配置集中
- `utils/config.js` 重构为环境化：`ACTIVE_ENV` + `ENVS{dev,lan,prod}`，派生 `SERVER/BASE_URL/UPLOAD_URL/USE_MOCK/TIMEOUT`
- 新增 `utils/img.js#resolve()/resolveList()`：把 `/uploads/...` 或旧域名统一改写为当前 SERVER
- 9 处 imageList 渲染点接入 resolve（首页/二手列表·详情·发布/表白墙·详情/帖子列表·详情·发布）

**验证**：前端 JS/JSON 全通过、11 页结构通过、mock 自测 89/89、后端编译 EXIT=0。

**关键提醒**：改完必须停服务 → `mvn clean install` → 重启；`clean` 报无法删除 target 就是进程没停。
