## 追加：修复「后端启动不了」（三层原因叠加）

**第 1 层：`campus-common` 从未装进本地仓库**
用户在 `campus-wall/` 目录直接 `mvn spring-boot:run` → `Could not resolve dependencies ... campus-common:jar:1.0.0`。
本地仓库里只有 `.lastUpdated`（下载失败标记），且真实仓库路径是 **`D:\apache-maven-3.6.3\MavenData`**（不是 `~/.m2`）。
→ 清掉标记，`mvn -DskipTests clean install` 全量安装。

**第 2 层：坏字节码**
install 后启动报 `NoClassDefFoundError: R`。`javap -s AuthController` 显示 `descriptor: (...)LR;`
——**返回类型被编译成默认包的 `R`**。原因是前一轮 `clean` 失败（target 被运行中进程占用）后直接增量 `compile`，
target 处于半损坏状态，复用了坏产物。→ `mvn clean install` 全量重建后恢复正常（`Lcom/campus/common/api/R;`）。

**第 3 层：环境变量污染（仅 WorkBuddy 执行环境）**
重建后 6 个服务仍全挂，报 `Port 61581 was already in use`。
`env` 里发现 **`SERVER__PORT=61581`**，Spring 的 relaxed binding 把它当成 `server.port`，
所有服务抢同一端口。→ 启动命令加 `env -u SERVER__PORT` 绕过。用户自己的终端/IDEA 无此变量。

**结果**：6 个服务全部启动，`scripts/api-smoke-test.js` **16/16 通过**，
`/schools`、`/goods`、`/wall/posts` 均返回真实数据（15 件商品、8 条表白等种子数据完整）。

**经验**：启动失败先分层排查 —— 依赖能否解析 → 字节码是否正常（javap）→ 端口是否被环境变量劫持。

## 追加：修复「帖子详情 404 / 加载失败」（雪花 ID 精度丢失）

**现象**：帖表能显示，点进详情就「加载失败」。Network 里请求 id 是 `211353730977323000`
（末尾 3 个 0），而真实 id 是 `2113537302977323010`。

**根因**：雪花 ID 为 19 位 Long，超过 `Number.MAX_SAFE_INTEGER`（9007199254740991）。
后端以数字返回 → 小程序 `JSON.parse` 末位舍入 → 请求了不存在的 id → 404。
种子数据 id 小（8001/6001）所以一直没暴露，用户新发布的内容全是雪花 ID。
**商品、表白墙、订单、评论同理**。

**修复**
- 新增 `campus-common/config/JacksonConfig`：`serializerByType(Long/long, ToStringSerializer)`
  → 所有 Long 字段以字符串返回；计数类字段是 Integer，不受影响、仍可参与运算
- 前端去掉对服务端 id 的 `Number()` 转换（3 处）：
  `post/list.switchChannel`、`post/publish.chooseChannel`、`user/verify.pickSchool`
  （goods 的 categoryId 是 Integer，保留 Number 转换）
- `channelId` 默认值由 `0` 改为 `''`，WXML 选中判断改为 `!channelId` / 字符串相等

**验证**：`clean install` 后重启 6 服务，`/posts` 返回 `"id":"2113537302977323010"`（str）；
用该 id 取详情 `code:0`；`api-smoke-test` 16/16；前端 JS、11 页结构、mock 89/89 全通过。

**注意**：这是通用坑 —— 任何用雪花 ID 的项目都必须做 Long→String，否则小程序/H5 必踩。

## 追加：真机图片不显示 / 无图商品封面空白

**现象**：手机预览时商品封面空白；有图商品的图也看不到。

**原因**
1. 库里存的图片地址是 `http://127.0.0.1:8888/uploads/...`（后端 `campus.upload.base-url` 默认值）。
   模拟器里 127.0.0.1 = 电脑，能加载；**真机上 127.0.0.1 = 手机自己**，必然失败。
2. 无图商品的占位用的是 emoji（`{{item.emoji}}`），在部分环境下不渲染，表现为纯空白。

**修复**
- 封面图加 `binderror`：加载失败自动回退到占位图（`imgFailed` 标记），彻底避免白块
- 占位从 emoji 改为**纯 CSS 图标**（`.ce-icon` + `.ce-sun` + `.ce-hill`）+ 分类名文字，不依赖字体渲染
- 页面 wxss 里旧的 `.cover-empty` 定义删除，统一用 app.wxss

**验证**：`utils/img.js#resolve('http://127.0.0.1:8888/uploads/x.jpg')` → `http://192.168.0.2:8888/uploads/x.jpg` ✓；
局域网 `curl http://192.168.0.2:8888/uploads/...` 返回 200 ✓（服务端正常）。
**结论**：前端必须重新编译（清缓存），resolve 才会把历史数据里的 127.0.0.1 改写掉。

**真机自检方法**：手机浏览器打开 `http://192.168.0.2:8888/api/schools`，能看到 JSON 说明局域网可达；
打不开则是防火墙未放行 8888 或手机不在同一 WiFi。

## 追加：项目从 QQ 小程序迁移为微信小程序

**背景**：先做了兼容性评估（页面层/API 适配层已通用，登录链路 + 数据模型是 QQ 硬编码），用户要求直接改成微信版。

### 后端
- `t_user` 加 `platform VARCHAR(16)`，唯一键 `uk_openid(openid)` → **`uk_platform_openid(platform, openid)`**
  - 原因：openid 只在宿主平台内唯一，联合键才能同时保证「跨平台可同值」与「同平台内唯一」
  - **迁移脚本默认值必须给 `'qq'`**（历史 openid 来自 QQ），不是 `'wx'`
- `User` 实体加 platform；`LoginOrCreateReq` 加 platform
- `LoginReq` 加 platform（`wx`/`qq`，缺省 `wx`）
- `AuthService`：`campus.qq.*` → `campus.wx.*` + `campus.auth.mock`（环境变量 `WX_APPID/WX_APPSECRET/AUTH_MOCK`）；
  `code2Session(platform, code, devOpenid)` 双分支，`api.weixin.qq.com` / `api.q.qq.com`，参数名一致
- `UserService.loginOrCreate` 按 `(platform, openid)` 查询

**踩坑**：`campus-common` 和 `campus-user` 各有一个同名 `LoginOrCreateReq`
（前者是 Feign 契约，后者是服务端接收），**只改一个会编译失败**。

### 前端
- `utils/util.js`：宿主识别反转为 **wx 优先**，导出 `PLATFORM` / `PLATFORM_NAME`
- `utils/auth.js`：登录 body 带 `platform`
- 头像改微信新规范：`<button open-type="chooseAvatar" bindchooseavatar>` + `<input type="nickname">`；
  删除已废弃的 `getUserInfo` / `syncProfileQuietly` 静默授权链路
  - **chooseAvatar 给的是临时路径，必须先 upload 换 URL 再入库**（重启后临时目录被清理）
  - `<button>` 没有 `binderror`，别乱挂
- `app.json`：`selectedColor` 旧珊瑚粉 `#FF6B57` → `#11A86B`，背景 `#F6F7FB` → `#F5F6F8`，
  加回 `"style": "v2"`（微信支持，QQ 不支持，之前为 QQ 删掉了）
- `project.config.json`：删 `qqappid`，`libVersion` 1.10.0 → 3.0.0；`sitemap.json` 文档链接换微信
- `config.js`：补微信域名/HTTPS/合法域名说明

### 验证
- 后端 `mvn compile` EXIT=0；前端 JS/JSON/页面结构/事件绑定/WXML 标签全通过；mock 自检 96/96
- **数据库迁移已在真实库执行并验证**：`t_user` 联合唯一键行为实测
  - 跨平台同 openid 插入成功 → `PASS`
  - 同平台重复 openid 被拦 → `Duplicate entry 'wx-dev_openid_guizhou_campus_001'`
- `data.sql` 演示用户补 `platform='wx'`
- **接口冒烟未跑**：本机 Nacos(8848) 未启动，微服务起不来（MySQL/Redis 在）。需用户起 Nacos 后重启服务再验
