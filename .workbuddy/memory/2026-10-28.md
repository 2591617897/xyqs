## 私信页视频改为「点一下直接全屏播放」（00:20）

**诉求**：`pages/chat/index` 里别人（和自己）发的视频，原来气泡内是 `<video controls>` 小窗，点中央播放键只是内联播放；用户要点了就全屏。

### 改动
- `pages/chat/index.wxml`
  - 视频消息改成「封面卡」：`<video>` 关掉**全部**原生控件（`controls/show-center-play-btn/show-play-btn/show-fullscreen-btn/show-progress/enable-progress-gesture` 全 false），只负责渲染首帧
  - 上面盖一层 `.mv-hit`（透明铺满整卡，`catchtap="onTapVideo"`）+ 中央 `.mv-play` 白圈三角 + 右下 `.mv-dur` 时长
  - 页面末尾新增全屏播放层 `.vplayer`（`wx:if="{{vpShow}}"`、`catchtouchmove="noop"`）：顶部条 = 关闭键 + 「全屏播放中」，下方 `<video autoplay controls object-fit="contain" bindended="closeVideo">`
- `pages/chat/index.wxss`：`.msg-video` 变相对定位容器；`.mv-hit/.mv-play/.mv-dur`；`.vplayer/.vp-bar/.vp-close/.vp-body`
- `pages/chat/index.js`：`data.vpShow/vpUrl`；`onTapVideo / closeVideo / onVideoMeta / noop`；`fmtDuration()`；`onHide + onUnload` 收掉播放层（否则后台继续出声）
- `styles/icons.wxss`：新增 `.ico-play`（唯一新增图标，其余复用 `.ico-close`）
- 文档：`小程序项目档案.md` 的 `pages/chat/index` 一行补齐视频行为

### 关键决策（为什么这么写）
- **原生控件必须全关**：只要 `controls` 开着，点击落在原生控件层，`bindtap` 收不到，加 `bindtap` 也没用
- **热区铺满整卡而不是只包中央圆**：只盖圆的话用户点边上没反应；`.mv-hit` 透明铺满，点哪儿都进全屏
- **关闭键不能压在 video 上**：video 是原生组件，旧机型会盖住普通 view → 全屏层用「顶部条 96rpx + video 从 96rpx 往下」，关闭键永远在 video 区域之外，且布局不依赖 flex
- **时长自己算**：控件关掉后没人再显示 `00:02`，用 `bindloadedmetadata` 的 `e.detail.duration` 写回 `messages[i].durationText`
- 不改后端：私信表没有 poster/duration 字段，首帧靠 video 自身渲染，时长靠元数据，零迁移

### 验证
- `node --check` 通过；`check-miniprogram` 24+12 页通过
- 自写静态核对脚本（class 定义 / 事件方法 / 标签配对）：新增 13 个 class 全部有定义、5 个事件方法全部存在、标签无错配
- ⚠️ **本机 chrome headless 截图不可用**：`--headless=new --screenshot` 在本会话沙箱里静默失败（无输出、无文件、退出码 0），加 `--user-data-dir/--no-sandbox/旧式 --headless` 均无效 → 目检改走静态核对，视觉真机再确认

### 待真机确认
- 安卓/iOS 上 `<video>` 无控件时能否稳定显示首帧（个别机型黑屏则只剩播放键，功能不受影响）
- 全屏层 `autoplay` 是否直接起播（系统限制时用户手点一次中央播放键）

## 内容可见范围（发闲置 / 发帖子加开关，默认仅本校，可切同市可见）

- 需求：发布页加「可见范围」开关，默认只限本校，切换后同市都能看
- **字段命名 `visibility` 而非 `scope`**：列表接口的 `scope` 已经是「浏览范围」（浏览者视角），
  可见范围是内容自己的属性。同名会让 OR 嵌套查询极易写错。
  公共常量 `campus-common/.../content/Visibility`（SCHOOL / CITY / normalize / isCity）
- **过滤规则（goods / post 一致）**
  - 浏览本校：`school_id = 我的学校`（本校内容无论可见范围都可见，本校 ⊂ 本市）
  - 浏览本市：`school_id IN 同城 AND (visibility='city' OR school_id=我的学校)`
  - 游客 / 未选学校：只看 `visibility='city'`（沿用既有「schoolId=null 看全站」，未顺手收紧）
- 迁移 `sql/migration-20261028-visibility.sql`：**已在本地库执行**；
  两表 `visibility VARCHAR(16) NOT NULL DEFAULT 'school'`，历史 7 行自动回填 school（数据量小，无风险）
- 后端：Goods/Post 实体 + Req 加字段；`apply()` / `publish()` / `update()` 归一化落库；
  `page()` / `pageInternal()` 加过滤；新增 `assertVisible()` 在 `detail()` 校验（**404 而非 403**，不暴露内容存在性）
- 前端：`utils/visibility.js` + 两个发布页加选项卡片（默认 school、编辑回显、提交带 visibility）
- 自检 `scripts/visibility-selftest.js`（68 项）全绿；全量回归含 `db-schema-check`、`security-baseline-check` 均通过

### ⚠️ 硬坑：MyBatis Plus 悬空 OR
```java
// ❌ city 模式下 schoolId 为 null 时，or() 已追加关键字、后面 eq 不成立，
//    SQL 变成 "... AND (visibility = ? OR)" —— 整条 SQL 语法错误
w.and(q -> q.eq(Goods::getVisibility, CITY).or().eq(schoolId != null, Goods::getSchoolId, schoolId));

// ✅ 拆成两个分支
if (schoolId != null && schoolId > 0) {
    w.and(q -> q.eq(Goods::getVisibility, CITY).or().eq(Goods::getSchoolId, schoolId));
} else {
    w.eq(Goods::getVisibility, CITY);
}
```
自检里有一条专门盯住这个写法不被改回去。

### 另外两个易漏点
- 本市流**必须透传 `schoolScope` / `viewerSchoolId`**：原来 city 分支传 null，
  会让用户连本校同学发的仅本校内容都刷不到
- 只过滤列表不够：详情接口是独立入口，分享链接可直达，必须单独 `assertVisible()`，
  否则「仅本校」形同虚设

### 未做 / 待定
- 树洞（wall）暂未加（需求只提闲置和帖子）
- 列表卡片 / 详情页暂不展示可见范围标签，作者只能在编辑页看到自己设的值
- 游客仍可看到仅本校内容（沿用既有行为）；要收紧就改 `assertVisible()` 里「无学校身份放行」那条分支

## 需求广场（求物 / 求帮忙）立模块（第三十四轮）

需求：闲置只有「我要卖」，缺反向流 —— 用户想找东西、想找人帮忙。范围从「求购」扩成学生需求模块。

**定名**：需求广场 demand；两类 `1求物 / 2求帮忙`。红线仍是只做信息展示：
不接支付、不做担保、**不做评价打分**（有评分就变服务平台，类目资质不是一个量级）。
`budget` 允许 null = 面议，也是为了不让求助类需求看起来像悬赏任务平台。

**独立建表**（不给 t_goods 加 flow）：`t_demand` + `t_demand_reply`（`sql/migration-20261028-demand.sql`，已执行本地库）。
理由：t_goods 的成色/保修/入手时间/邮寄方式对需求全无意义；「已售出」vs「已找到」状态机不同；
混存后每条查询都要记得加 flow 过滤，漏一处需求就混进卖货列表。

**状态机**：发布→进行中(1)；已找到→已完成(2)；下架→已下架(0)；两者都能重新开放回 1。
列表只查 status=1，已完成/已下架不占广场。

**回应方向是反的**：t_goods_order 是买家找卖家，需求是「有货的人」找发布者 → 单独 t_demand_reply。
`contact` 用 EncryptedStringTypeHandler（与 t_goods_order.contact 同性质）。

### 硬约束（改这块前必读）
- **两套分类 id 各自从 1 开始**（求物 7 项 / 求帮忙 6 项）→ 任何按 category_id 查询**必须带 type**；
  前端换大类必须清 categoryId（list / publish 两处都做了）
- **一人一需求只能一条回应**：否则一个人能刷屏发布者的列表
- **回应列表只有发布者能拉**；网关 `PRIVATE_SEGMENTS` 加了 `replies`，游客 GET 直接 401
- **路径 `/demands/replies/mine` 刻意带 mine 段**：网关按路径段判私域，用 `my-replies` 会被 PUBLIC_READ 放行
- **删需求级联删回应**，否则「我发出的回应」指向 404 的需求
- **发布前必须 upload.uploadImages 换服务端 URL**（wxfile:// 入库 = 别人永远加载不出来）
- ⚠️ **上线必须重启网关**（新增 `/api/demands/**` 路由），否则整模块 404
