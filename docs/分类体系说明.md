# 分类体系说明（树洞 / 闲置 / 频道）

> 2026-10-27 整理。改任何分类相关代码前先看这份，别只看页面效果。
> 落地实现见 `miniprogram/utils/wall.js`、`GoodsService.CATEGORIES`、`t_channel`，
> 一致性由 `scripts/category-tidy-selftest.js` 兜底（40 断言，跑不过就是有问题）。

---

## 一、整理前的问题

三个模块的分类各写各的，互相重叠，同一件事有多个入口：

| # | 问题 | 具体表现 |
|---|---|---|
| 1 | 树洞首个 tab 名不符实 | 标签叫「💗 校园心情」，但代码里是 `if (cat !== 'love') query.category = cat` —— 它就是**全量流**。用户以为在筛心情，其实看的是全部 |
| 2 | 寻物 / 寻人散在两处 | 树洞有「🔎 寻物启事」「🙋 寻人互助」两个分类，频道「📢 校园公告」的描述里又写着「失物招领」 |
| 3 | 频道抢了树洞的主场 | 频道 2004「树洞吐槽」与树洞分类 `tree` 完全同义 |
| 4 | 频道抢了闲置的主场 | 频道 2005「二手交易」＝ 独立的闲置模块，但频道里的闲置不走闲置的品类筛选、搜索热词、推广加权 |
| 5 | 闲置品类有垃圾桶 | 「生活」「其他」什么都能塞，校园最高频的自行车/电动车只能硬塞进「运动」或「其他」 |
| 6 | 品类表两处维护 | 后端 `GoodsService.CATEGORIES` + 前端 `util.js` 的 `CATEGORY_EMOJI`，加一个品类要改两处，容易漂 |
| 7 | 频道没有上下线机制 | `t_channel` 没有 `status`，想下线一个频道只能 DELETE，而 `t_post.channel_id` 有引用，删了历史帖子就丢频道名 |
| 8 | 首页副标题写死话题名 | `zones.js` 里硬编码「吃喝玩乐 · 树洞吐槽 · 运动搭子」，频道一改就对不上 |

## 二、整理原则

**一个模块只回答一个问题，模块之间不抢活。**

| 模块 | 回答的问题 | 分类维度 |
|---|---|---|
| 树洞 | 我现在什么心情 / 需要什么帮忙 | 情绪与诉求 |
| 闲置 | 我在卖什么品类的东西 | 物品品类 |
| 频道 | 大家在一起聊什么公共话题 | 公共话题 |

按「物品」分类的只有闲置，按「情绪」分类的只有树洞，按「话题」分类的只有频道——
任何一条内容只该属于一个模块，用户不用猜该发在哪。

## 四、数据层约定（改之前必读）

1. **品类 id 只能追加，不能重排。** 见上。
2. **频道下线用 `status=0`，不要 DELETE。** `t_post.channel_id` 有引用，
   删行会让历史帖子丢频道名；下线后 `/channels` 不返回，但详情页仍能按 id 解析出名字。
3. **树洞分类是字符串枚举，只认白名单。**
   发布走 `normalizeCategory()`（单值，非法回落 `love`）；
   查询走 `parseCategories()`（逗号拆多值 + 白名单过滤 + 去重，空/全非法 = 不过滤）。
4. **前端 `CATEGORY_EMOJI` 必须与后端 `CATEGORIES` 同步。**
   列表接口只返回 `categoryId`，不带 icon，所以前端留一份兜底表；
   chips 则走 `/goods/categories` 用接口的 icon。漂了自测会失败。
5. **分类定义只有一个源。**
   树洞 = `utils/wall.js` 的 `CATS`（页面不再内联数组）；
   闲置 = 后端 `GoodsService.CATEGORIES`；频道 = 数据库。

## 六、回退方法

只改了数据、没有删数据，回退不难：

```sql
-- 恢复两个频道
UPDATE t_channel SET status = 1 WHERE id IN (2004, 2005);
-- 彻底回退字段（可选）
ALTER TABLE t_channel DROP COLUMN status;
```

代码侧回退：`git revert` 本轮提交即可，`t_goods` / `t_wall_post` 没有数据迁移，
「代步」只是多了一个可选 id，不回退也不会坏。

## 七、以后加分类怎么加

### 加一个闲置品类

1. 后端 `GoodsService.CATEGORIES` 追加 `new CategoryVO(新id, "名字", "emoji")`，位置决定展示顺序；
2. 前端 `utils/util.js` 的 `CATEGORY_EMOJI` 加同一条（emoji 必须一致）；
3. 跑 `node scripts/category-tidy-selftest.js`，会校验两边是否对齐。

不需要改页面 —— 列表页 chips 和发布页都读 `/goods/categories`。

### 加一个树洞分类

1. `utils/wall.js` 的 `CATS` 加一条（`key` / `name` / `tag` / `query`）；
2. `CAT_TAG` 加对应标签；
3. 后端 `WallService.CATEGORIES` 白名单加同一个 key；
4. 跑 `category-tidy-selftest.js`（会双向校验：前端发的后端要认，后端的不能没入口）。

### 加一个频道

直接在 `t_channel` 插一行 `status=1` 即可，后端 `/channels` 和首页功能区自动多一个入口，
前端不用改代码。

### 下线一个频道

```sql
UPDATE t_channel SET status = 0 WHERE id = xxx;
```

不要 DELETE。
