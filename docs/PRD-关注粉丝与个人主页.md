## 一、项目信息

| 项 | 内容 |
| --- | --- |
| Language | 简体中文 |

**原始需求复述**：在「校园趣事」小程序中实现关注/粉丝功能（关注、取消关注、粉丝数、关注数）；完善「我的」页面，体现关注/粉丝相关入口或数据；点击任意用户的头像或昵称（首页信息流帖子卡片、闲置详情卖家卡、帖子详情作者头部等位置）跳转到该用户的个人介绍页；个人介绍页展示对外可见信息（头像、昵称、学校、认证状态、粉丝量、关注数）以及该用户发布的帖子、闲置交易记录；在个人主页上可对该用户进行关注/取消关注操作。

---

## 二、产品定义

### 2.1 产品目标

1. **建立同校用户间的关注关系链**：补齐「关注 / 取消关注 / 粉丝数 / 关注数」完整闭环，为交易信任与社区互动提供社交基础能力。
2. **提供统一的个人介绍页**：作为用户对外名片，聚合校园身份、社交数据与历史内容（帖子 + 闲置），让「点头像就能了解 TA」成为全站一致体验。
3. **打通「发现人 → 了解人 → 关注人」最短路径**：在信息流、闲置详情、帖子详情三个高频场景完成入口改造，提升用户留存与交易转化。

### 2.2 用户故事

1. 作为浏览首页的登录用户，我想在信息流中点击作者头像或昵称进入 TA 的个人主页，以便在关注前先了解其校园认证与历史发布内容。
2. 作为闲置详情页的买家，我想查看卖家的认证状态、在售与累计发布数量，并关注卖家，以便持续看到 TA 后续发布的好物。
3. 作为帖子读者，我想从作者头部进入作者主页并关注持续输出的同校同学，以便建立校园社交联系。
4. 作为平台用户，我想在「我的」页面看到自己的关注数与粉丝数，并进入关注/粉丝列表管理关系，以便掌握自己的社交网络。
5. 作为内容发布者，我想通过积累粉丝提升自己在校园社区的影响力与交易可信度。

### 3.2 关键页面与交互说明（结合 4 张设计稿）

#### A. 新页面：`pages/user/space` 个人介绍页（无设计稿，沿用「我的」页视觉规范）

- **导航栏**：返回 + 「个人主页」标题。
- **头部卡**（绿色渐变，同「我的」页 hero 风格）：
  - 头像 + 昵称 + 认证徽章（✓ 已认证 / 未认证）+ 学校（🎓 xx大学）+ bio（如有）。
  - 数据行：**关注数 · 粉丝数**（P2 可扩展获赞与收藏）。
  - 关注按钮（右上或右下主按钮）：
    - 未关注 → 「+ 关注」（主色实心）；
    - 已关注 → 「已关注」（幽灵样式，再次点击取消，弹确认或直接取消 + toast「已取消关注」）；
    - 本人进入 → 不显示关注按钮，显示「编辑资料」。
- **内容 Tab**：「帖子 / 闲置」，默认「帖子」；闲置项带状态标签（在售中 / 已售出 / 已下架）与价格。
- **空态**：「还没有发布内容」。
- **登录态**：未登录可浏览；点击关注按钮走现有 `auth.ensureLogin()` 模式，登录后自动继续关注操作。
- **乐观更新**：点击关注 → 按钮立即切换 + 粉丝数 +1 → 请求失败回滚并 toast「操作失败，请重试」；按钮 loading 期间防重复点击。

#### B. 入口 1：首页信息流（设计稿 2：帖子卡片带作者头像昵称、闲置卡片带卖家信息）

- 帖子卡作者行：**头像 + 昵称区域点击 → 跳个人介绍页**（阻止冒泡；卡片整体仍跳帖子详情）。
- 帖子卡右上「+ 关注」按钮：P1 实现真实关注/取消（R9）。
- 闲置卡作者行（头像 + 昵称）同样支持点击跳转；右侧保留「闲置中」标签。

#### C. 入口 2：闲置详情页卖家卡（设计稿 3：林小满 / 已实名学生认证 / 同校同学 / 在售 2 件 / 累计发布 2 件 +「关注」按钮）

- 卖家卡：**头像 + 昵称点击 → 跳个人介绍页**。
- 「关注」按钮（当前 `onFollow` 为占位 toast「关注功能即将上线」）：P1 实现真实关注/取消，关注后文案变「已关注」。
- 底部「聊一聊」「申请自提」、收藏、评论等既有流程不变。

#### D. 入口 3：帖子详情页作者栏（设计稿 4：未名风 / 44 分钟前 / 学习交流 +「同校」按钮）

- 作者栏：**头像 + 昵称点击 → 跳个人介绍页**。
- 右上「同校」按钮：维持静态同校标签（设计稿语义），不改为关注按钮；关注统一在个人主页完成。

#### E. 「我的」页面（设计稿 1：个人主页头部统计、校园信用分、我的交易、社交互动）

- 统计条（我发布的 / 已卖出 / 我的动态 / 赞与收藏）保持 4 项布局与既有跳转不变。
- 「社交互动」区新增「我的关注」入口（副文案显示关注数），点击跳转关注/粉丝列表页（P1，R10；P0 阶段可先跳个人主页或 toast 占位）。
- 本人关注数 / 粉丝数随 `/user/me` 或 `/user/{自己id}/profile` 一并获取展示。
- 说明：统计条当前数字为写死值，真实化属 P1（R11），不在 P0 范围。

### 3.3 接口清单（前端视图，均经网关 `/api` 前缀）

| 方法 | 路径 | 优先级 | 说明 |
| --- | --- | --- | --- |
| POST | `/user/follow/{userId}` | P0 | 关注（需登录）。幂等：已关注则直接返回成功，不重复计数。返回 `{following:true, fansCount}` |
| DELETE | `/user/follow/{userId}` | P0 | 取消关注（需登录）。未关注时返回成功。返回 `{following:false, fansCount}` |
| GET | `/user/follow/status?userId=` | P0 | 当前登录用户对 `userId` 的关注状态 → `{following}`；未登录返回 `false` |
| GET | `/user/{userId}/profile` | P0 | 🔓 他人公开主页资料与统计（字段见 R3） |
| GET | `/posts?userId=&page&size` | P0 | 帖子列表增加 `userId` 过滤 |
| GET | `/goods?userId=&page&size` | P0 | 闲置列表增加 `userId` 过滤（建议同时支持 `status` 区分在售/已售出） |
| GET | `/user/me/following?page&size` | P1 | 我的关注列表 |
| GET | `/user/me/fans?page&size` | P1 | 我的粉丝列表 |

> 现有 `/internal/users/**` 内部接口与消息中心 `followers` 汇总字段不受影响；内部接口不暴露关注关系。

### 3.4 数据设计（移交架构师 / 后端）

```sql
CREATE TABLE IF NOT EXISTS t_follow (
  id          BIGINT      NOT NULL PRIMARY KEY COMMENT '雪花ID',
  follower_id BIGINT      NOT NULL COMMENT '关注者（谁发起关注）',
  followee_id BIGINT      NOT NULL COMMENT '被关注者',
  created_at  DATETIME    DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_pair (follower_id, followee_id),
  KEY idx_followee (followee_id, created_at),
  KEY idx_follower (follower_id, created_at)
) COMMENT '关注关系';

ALTER TABLE t_user ADD COLUMN fans_count   INT NOT NULL DEFAULT 0 COMMENT '粉丝数' AFTER bio;
ALTER TABLE t_user ADD COLUMN follow_count INT NOT NULL DEFAULT 0 COMMENT '关注数' AFTER fans_count;
```

实现要点：

- **计数维护**：关注 / 取消在同一事务内更新 `t_user` 两行计数（被关注者 `fans_count +1`、关注者 `follow_count +1`）；取消时反向 `-1` 且不小于 0；与仓库现有计数器风格（`like_count` / `comment_count`）保持一致。
- **服务归属**：`t_follow` 由 campus-user（8102）拥有，沿用多服务共库（`guizhou_campus_fun`）现状。
- **ID 传输**：雪花 ID 全局序列化为字符串，前端透传不做 `Number()` 转换。
- **越权与风控**：不能关注自己；被封禁用户不可被关注且主页返回 404。
