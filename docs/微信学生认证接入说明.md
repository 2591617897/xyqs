# 微信学生身份认证 · 接入说明

> 代码已完整实现，默认**关闭**。开启前请先读完第 1、2 节——这个能力有两个硬性准入条件，
> 不满足时接口会一直返回 `48001 无 api 权限`，不是代码问题。

---

## 0. 结论先看

| 项目 | 状态 |
|---|---|
| 后端链路（auth 调微信、user 落库、重签 token） | 已实现，编译通过 |
| 小程序双通道认证页（微信认证 / 上传学生证） | 已实现，默认只显示学生证通道 |
| 数据模型（`verify_source` 等 4 列） | 已实现，需执行迁移脚本 |
| 能力是否申请得下来 | **不确定，先看第 2 节的类目与用途限制** |

关键判断：微信这个能力**不是通用的「学生身份校验」**，它要求「用途是给学生提供优惠活动」，
并且服务类目必须在官方白名单里。「社交 - 社区 / 论坛」不在白名单，所以要么申请时说明
后续会提供学生权益（并真的去做），要么就走学生证通道——代码两条路都留着，开关一关即可。

## 1. 能力边界（决定了产品怎么设计）

官方接口 `POST /intp/quickcheckstudentidentity` 的返回只有四个字段：

```json
{ "errcode": 0, "errmsg": "ok", "bind_status": 3, "is_student": true }
```

所以：

- **拿不到学校** → 认证页仍然要用户自己选学校（本站的「同校」分区依赖 `school_id`）
- **拿不到姓名、学号** → 走这条通道的用户 `real_name` / `student_no` 为空，
  页面不能再用「已认证 == 有学号」这个假设（`profile.wxml` 已改为显示「微信核验免填」）
- **拿不到学历、毕业时间** → 没有「大几」「毕业年份」这类派生字段
- 覆盖范围：内地普通高校在读（专科 / 本科 / 硕博），仅支持二代身份证的大陆居民
- 同一学生身份只能绑一个微信；毕业到期后微信侧自动解绑，我方 `verify_status` 不会自动变
- 首次走「快速验证」，快速验证没过的用户可以补充学籍信息继续验证（仍是同一个 code 流程）
- 单日限额 100 万次，目前免费

## 2. 准入条件（这里是真正的卡点）

小程序后台 → 功能 → 学生验证，申请时必须同时满足：

| 条件 | 本项目情况 |
|---|---|
| 主体为境内非个人主体 | 需你确认营业执照类型 |
| 已完成微信认证 | 需确认 |
| 近 3 个月无严重违规记录 | 需确认 |
| **用途为向学生用户提供优惠活动**，接入后需上传实际优惠信息 | ✘ 我们的用途是「校园身份校验」，需要在申请材料里写成「面向在校学生的专属权益 + 社区准入」，并准备真实优惠（如校园闲置免推广费、学生专属活动） |
| **服务类目在官方白名单** | ✘ 白名单：教育服务、物流、交通、生活服务（求职/招聘、演出票务）、IT科技、工具（办公）、电商平台、餐饮、旅游、商家自营、商业服务（摄影）、金融（银行）、文娱（音乐）。**「社交 - 社区/论坛」不在其中** |

建议：

1. 先在后台点「学生验证」看是否直接提示类目不满足——不满足就不必投入联调时间；
2. 若确实要接，和审核同学沟通「用学生权益场景申请」，并在审核通过后 30 天内上架学生优惠；
3. 拿不到授权也没关系，学生证通道是完整可用的（`auto-approve` 可配置）。

## 3. 全链路

```
小程序认证页
  └─ <studentVerify show isQuick>  ← 微信学生身份验证插件（appid wxa16657d57059e0f0）
        └─ bind:auth → e.detail.wx_studentcheck_code（2 小时有效、一次性）
              └─ POST /api/user/verify/wx-student { schoolId, code }
                    └─ campus-user  UserService#submitWxStudentVerify
                          └─ Feign /internal/wx/student/check { userId, code }
                                └─ campus-auth  WxStudentService#check
                                      ├─ 查 t_user.openid（code 必须与 openid 匹配）
                                      ├─ 复用 WxSecurityService 的 access_token 缓存
                                      └─ POST api.weixin.qq.com/intp/quickcheckstudentidentity
                    └─ 通过 → verify_status=2 / verify_source=2 / 重签 JWT
```

设计取舍：

- **为什么核验在 campus-auth**：appid / secret / token 缓存都在那里。各服务自己刷 token 会互相顶掉
  （同一 appid 刷新会让旧 token 失效），表现为随机 `40001`。所以 `WxSecurityService#accessToken`
  改成 public 供复用，**不要再写第二份 token 逻辑**。
- **为什么 user 只传 userId 不传 openid**：openid 跨服务传会把身份凭据扩散到业务层，
  auth 侧已有 `WxOpenidMapper` 直读能力。
- **为什么用 JDK HttpClient**：Spring 的请求工厂会把 POST 退化成 chunked，
  微信对 chunked 直接回 HTTP 412 且无响应体（内容安全踩过同一个坑）。
- **code 不落库**：一次性凭据 + 可查学籍，落库只有风险没有收益。

## 5. 开通步骤

1. 小程序后台确认主体、微信认证、违规记录都满足；
2. 「功能 → 学生验证」提交申请，用途填写**学生专属权益 + 校园社区准入**，附交互图与优惠明细，等 3-5 个工作日；
3. 通过后：「设置 → 第三方设置 → 插件管理」添加「微信学生身份验证」；
4. **跑迁移脚本（不跑会全站登录失败，必须先做）**：
   ```bash
   # 幂等脚本，可重复执行；库名用 -D 指定
   mysql -u root -p -D guizhou_campus_fun < backend/sql/migration-20261027-wx-student-verify.sql
   # 校验：应输出 4 列
   mysql -u root -p -N -e "SHOW COLUMNS FROM guizhou_campus_fun.t_user LIKE 'verify_source'"
   ```
   > ⚠️ 后端代码（`User` 实体）一旦带上这 4 个字段，库里没有就会让
   > **每一条 `select t_user` 都 `Unknown column`**，表现是「微信登录失败，请重试」，
   > 登录、我的页、发布一起挂。本地/线上都要跑，别只在本地跑。
   > 本地可用 `node scripts/db-schema-check.js` 一键比对 47 个实体的字段与真实库列。
5. 后端环境变量：`WX_STUDENT_VERIFY=true`，重启 campus-auth（配置只在启动时读）；
6. 前端打开插件：
   ```bash
   node scripts/wx-student-plugin.js on
   ```
   然后重新编译。**顺序不能反**：先加插件、再改 app.json，否则开发者工具会直接编译失败。
7. 后台「学生验证 → 添加测试账号」：只能加本项目的项目成员/体验成员，加完还要用那个微信号
   在小程序里真正走一次验证，才会有测试学生身份。

## 6. 配置项

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `WX_APPID` / `WX_APPSECRET` | 已配 / 空 | 学生核验与内容安全共用 |
| `WX_STUDENT_VERIFY` | `false` | 能力总开关。false 时接口直接回「暂未开通，请改用学生证认证」 |
| `WX_STUDENT_VERIFY_MOCK` | `false` | 跳过微信直接放行，**生产必须 false**，基线自检会拦 |
| 前端 `WX_STUDENT_VERIFY` | `false` | 与后端开关独立：前端管入口，后端管能力 |

> 两个开关要一起开。只开前端 = 用户点了按钮没反应；只开后端 = 页面看不到入口（不影响学生证通道）。

## 7. 接口契约

**请求**

```
POST /api/user/verify/wx-student      （需登录，网关注入身份）
{ "schoolId": "1001", "code": "wx_studentcheck_code..." }
```

**成功**

```json
{
  "code": 0,
  "data": {
    "verifyStatus": 2,
    "token": "新的 JWT（含最新 schoolId / vs）",
    "message": "微信学生认证通过，欢迎来到校聚一城"
  }
}
```

前端必须用返回的 token 覆盖本地（`mp.setStorageSync('token', ...)` + `auth.markTokenFresh()`），
否则「我的」页仍是未认证——JWT 里的 `vs` 是登录时的快照。

**错误话术映射**（后端已翻译，前端直接 toast `msg`）

| 微信 errcode | 用户看到的话 |
|---|---|
| 40097 | 认证信息与当前微信账号不匹配，请重新发起认证 |
| 83400 | 本次认证已超时，请重新点击微信认证 |
| 83401 | 今天查询学生身份的次数已达上限，请明天再试或改用学生证认证 |
| 83402 | 认证场景不匹配（需快速验证），请升级微信后重试 |
| 48001 / 61007 | 小程序尚未开通微信学生认证能力，请改用学生证认证 |
| -1 | 微信侧系统繁忙，请稍后再试 |
| `bind_status=2` | 微信正在核验你的学籍，请稍后再查看 |
| `bind_status=3` 但 `is_student=false` | 微信未确认你的学生身份，可改用学生证认证 |

## 8. 数据模型

```sql
verify_status        -- 不变：0未认证 1审核中 2已认证 3驳回（是否认证只看这列）
verify_source        -- 新增：1 学生证材料  2 微信学生认证
wx_student_verified  -- 新增：微信侧是否核验通过
wx_student_status    -- 新增：bind_status 留档（申诉复核用）
wx_student_verify_at -- 新增：通过时间
```

历史数据处理：`UPDATE ... SET verify_source = 1 WHERE verify_status = 2`，已包含在迁移脚本里。

## 9. 本地联调

能力没开通时也能把页面和数据流跑通：

```bash
# 后端（auth 服务）
WX_STUDENT_VERIFY=true
WX_STUDENT_VERIFY_MOCK=true      # 直接返回「已认证」
```

前端仍需插件才能弹窗。没有授权时插件拉不起来，可以临时只验证接口：

```bash
curl -X POST https://campus-api.trkcwl.com/api/user/verify/wx-student \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"schoolId":"1001","code":"mock-code"}'
```

> `mock-code` 只在 `WX_STUDENT_VERIFY_MOCK=true` 时有效；真实模式下必定 40097。

真机验证顺序：开发者工具编译 → 真机预览 → 点「开始微信认证」→ 微信弹层 →
授权 → 回到小程序看是否直接变成「已认证」。开发者工具里插件弹层可能不完整，以真机为准。

## 11. 不接入时的降级

- 前端：`node scripts/wx-student-plugin.js off`，认证页只剩「上传学生证」，不影响编译与发版
- 后端：`WX_STUDENT_VERIFY=false`，接口返回「暂未开通」，不会再打到微信
- 已通过微信认证的老用户：`verify_status=2` 不变，只是 `verify_source=2`，
  后续如果需要学号（比如按学号查重），会提示他们补充材料
