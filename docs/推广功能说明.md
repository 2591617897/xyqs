# 内容推广：看激励视频换排序

> 适用范围：闲置商品（GOODS）、校园帖子（POST）、表白墙（WALL）
> 实现版本：2026-10-27

---

## 1. 用户视角

1. 打开**自己发布**的内容 → 点「🚀 推广」
2. 弹层显示当前推广分、今日剩余次数、有效期
3. 点「看视频，+100 推广分」→ 拉起微信激励视频广告
4. **看完整段视频** → 提示「推广成功，+100 分」，内容在同校列表里往前排
5. 中途退出 / 广告加载失败 → 不计分，且不消耗当日次数

排序规则：**默认（最新）排序下推广分高的排在前面**，推广分 7 天内按剩余时间线性衰减到 0。
价格、热度排序是用户显式选的维度，不插入推广权重。

---

## 2. 计分与衰减

| 项 | 值 | 说明 |
| --- | --- | --- |
| 单次基础分 | 100 | 看完整段视频一次 |
| 有效期 | 7 天 | 从结算那一刻起算 |
| 衰减方式 | 线性 | 有效分 = 基础分 × 剩余时间 / 7 天 |
| 单条内容上限 | 5 次/天 | |
| 单账号上限 | 20 次/天 | 所有内容合计 |

看 3 次的第 3 天，分数大致是 `100×(5/7) + 100×(6/7) + 100×(7/7)`，越新的推广越重。
定时任务每 30 分钟重算一次「仍有推广记录」的内容并回写 `promote_score`，
所以列表排序是随时间自然回落的，不是一次性置顶。

---

## 3. 防刷设计（关键）

「看完广告」这件事只有客户端知道，服务端无法直接验证。链路设计成
**签发凭证 → 播放广告 → 凭凭证结算**，服务端至少能校验四件事：

| 校验 | 位置 | 说明 |
| --- | --- | --- |
| 凭证一次性 | `uk_nonce` 唯一键 + 带 `status=0` 的条件更新 | 并发重复结算只有一次生效 |
| 最短观看时长 | `issued_at → now >= 15s` | 跳过广告直接打结算接口会被拒 |
| 凭证有效期 | 10 分钟 | 超时自动作废 |
| 归属 + 配额 | 向内容服务查作者 + 每日次数 | 只能推广自己的，且每天有上限 |

**已知边界**：客户端仍可伪造「看完了」，但成本从「一次请求」变成「一次请求 + 等 15 秒」，
再叠加每日上限，对本项目的量级足够。**不要在服务端对这类上报做 fail-open**。

## 4. 服务端结构

### 新增服务 `campus-promote`（8108）

网关前缀 `/api/promote/**`，全部接口要求登录。

| 接口 | 作用 |
| --- | --- |
| `GET /promote/quota?targetType=&targetId=` | 当前分、今日剩余次数、规则参数 |
| `POST /promote/issue` | 签发一次性凭证（此时不加分） |
| `POST /promote/complete` | 看满时长后结算加分 |
| `POST /promote/cancel` | 放弃/失败时作废，释放配额 |
| `POST /promote/refresh` | 手动触发一次衰减重算（排障用） |

### 表

- `t_promote_record`：观看流水。`weight` 记衰减前的满分值，流水不随衰减改写。
- 三张内容表新增 `promote_score` / `promote_expire_at`（见 `sql/migration-20261027-promote.sql`）。
  字段必须落库：列表要按它排序，读时聚合没法走索引。

### 内容服务改动

`campus-goods` / `campus-post` / `campus-wall` 各自新增两个内部接口（不经过网关）：

- `GET /internal/{goods|posts|wall/posts}/owner?id=` → 作者 id（归属校验）
- `POST /internal/{...}/promote/apply` → 回写 `promote_score`（幂等）

promote 服务不直接写别人的表，走 Feign。

## 5. 配置

`campus-promote/src/main/resources/application.yml`：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PROMOTE_AD_UNIT_ID` | 空 | **微信激励视频广告位 ID**，正式投放必填 |
| `PROMOTE_MOCK_AD` | false | 联调模式，跳过真实广告。**生产必须 false** |
| `PROMOTE_BASE_SCORE` | 100 | 单次基础分 |
| `PROMOTE_DECAY_DAYS` | 7 | 有效期（天） |
| `PROMOTE_MIN_WATCH_SECONDS` | 15 | 最短观看时长 |
| `PROMOTE_DAILY_PER_TARGET` | 5 | 单条内容每天上限 |
| `PROMOTE_DAILY_PER_USER` | 20 | 单账号每天上限 |
| `PROMOTE_TOKEN_TTL_MINUTES` | 10 | 凭证有效期 |

`start-all.bat` 里本地默认 `PROMOTE_MOCK_AD=true`（未开通流量主时流程走不通），
**正式环境必须在启动脚本/系统环境变量里显式置为 false**。

---

## 6. 上线步骤

1. 小程序开通**流量主**（个人主体需满足累计独立访客等条件）
2. 流量主后台创建**激励视频广告位**，拿到 `adunit-xxxxxxxx`
3. 服务端配 `PROMOTE_AD_UNIT_ID=adunit-xxxxxxxx`、`PROMOTE_MOCK_AD=false`，重启 promote
4. 真机验证：点推广 → 能拉起广告 → 看完加分 → 列表排序变化
5. 广告位有地域/频次限制，首次可能报「无广告库存」，属正常

开发者工具里激励视频**拉不起来**（没有真实广告环境），本地联调请用 `PROMOTE_MOCK_AD=true`，
此时前端走「模拟观看倒计时」，服务端的最短观看时长校验照旧生效。
