## 零、快速定位：群入口为什么不显示

消息页群卡片有三个互斥状态，看屏幕上出现哪一个就知道卡在哪：

| 屏幕显示 | 含义 | 说明 |
|---|---|---|
| 只有四宫格，下方直接是「全部消息/闲置/…」 | 群接口失败（本次故障） | `GET /groups/mine` 没通 |
| 「选择学校，加入校友群　去选择」 | 用户 `schoolId=null` | 正常引导，点去选校即可 |
| 「登录后加入校友群　去登录」 | 游客态 | 正常 |
| 「校友群加载失败　点这里重试」 | 接口失败（2026-10-27 新增兜底） | 以前这种情况卡片会**整块消失**，看着像功能没做 |
| 「校友群　N 人」 | 正常 | — |

一条命令确认是不是后端问题：

```bash
curl -D - -o /dev/null https://campus-api.trkcwl.com/api/groups/mine
```

| 返回 | 结论 | 去做什么 |
|---|---|---|
| **404** | **网关没有 `/api/groups` 路由** | 网关跑的是旧包 → 见第一节 |
| 401 | 路由已生效，只是没登录 | 正常。带 token 再测 |
| 500 / 502 | 路由有了但 campus-message(8106) 没起 | 见第二节 |

> ⚠️ 404 和 401 必须分清：**404 = 无路由 = 包是旧的**，不是权限问题。这是本次踩的坑。

## 二、顺序执行（顺序不能乱）

```bash
# 1) 线上库迁移（本地库有表 ≠ 线上有表，数据源走 MYSQL_HOST env）
mysql -h<线上HOST> -u<user> -p guizhou_campus_fun < backend/sql/migration-20261027-group-chat.sql

# 验证 6 张表 + 菜单
mysql -h<线上HOST> -u<user> -p -N -e "
  select table_name from information_schema.tables
   where table_schema='guizhou_campus_fun' and table_name like 't_group%';"
# 期望 6 行：t_group / t_group_member / t_group_message / t_group_mention / t_group_mute / t_group_message_archive
```

```bash
# 2) 停旧服务 → 换 jar → 起新服务（4 个）
#    campus-message(8106) / campus-gateway(8888) / campus-admin(8107) / campus-user(8102)
#    campus-common 是依赖库，不用单独起

# 3) Nginx：加了独立的 /api/ws location，必须 reload
nginx -t && nginx -s reload
```

> Nginx 里 `/api/ws` 必须**写在 `location /` 之前**。`location /` 里的
> `proxy_set_header Connection ""`（keepalive 用）会覆盖 Upgrade 头，WS 握手直接失败。

## 三、微信后台配置（最容易漏的一项）

**服务器域名 → socket 合法域名** 加：

```
wss://campus-api.trkcwl.com
```

⚠️ 这和 `request` / `uploadFile` / `downloadFile` 是**四个独立项**，前三项配了不代表 socket 能连。

漏配的表现很有迷惑性：`wx.connectSocket` 失败 → 前端自动降级成轮询 → 消息**照样能收发**，
只是没有实时感、断线要等下一轮。很容易误判成「WS 代码写错了」去查后端。

> 开发者工具里勾了「不校验合法域名」时会正常，所以**工具里测不出这个问题**，必须真机才算数。

`WS_PUBLIC_URL` 不用配：前端 `subpackages/msg/utils/ws.js` 会用 `BASE_URL.replace(/^http/,'ws') + '/ws'` 自己推。

## 四、验证（按顺序点，每步都有明确预期）

| # | 操作 | 预期 |
|---|---|---|
| 1 | `curl -D - https://.../api/groups/mine` | **401**（不是 404）→ 路由已生效 |
| 2 | 打开消息页（账号 `schoolId=1001`） | 出现「校友群」卡片，N 人 |
| 3 | 查库 | `select * from t_group where biz_key='1001'` 有 1 行；`t_group_member` 有我 |
| 4 | 点卡片进群 | 首次弹**群规 + 安全提示**全屏层，点同意后写入 `rules_agreed=1` |
| 5 | 发一条消息 | 气泡立刻出现（乐观渲染），`t_group_message` 落库，`t_group.last_msg_id` 变了 |
| 6 | 另一台设备/另一账号同校进群 | 消息**实时**到达（能实时 = WS 通了；要刷新才有 = 降级到轮询了，回去查 socket 域名） |
| 7 | 断网 10 秒再恢复 | 重连后**自动补拉**断网期间的消息，不丢 |
| 8 | 别人 @ 我 | 消息页群卡片显示 `@1` 角标（**@ 角标优先于普通未读数字**） |
| 9 | 把 `night_start` 改到当前时间附近，再发消息 | 提示「夜间静默时段」，且**不是**提示「发太快」 |
| 10 | 后台群管理页 | 列表有群；抽屉四个 tab（群配置/成员/消息/禁言记录）都能加载 |
| 11 | 后台给某人设群管理员 | `t_group_member.role=1`，该账号夜间静默期间能发言 |

## 五、本次修掉的两个坑（避免重复排查）

1. **后台菜单 ID 撞车**：原用 9310 段与已有「系统日志」子树冲突，`INSERT IGNORE` 静默丢掉父节点 →
   菜单不显示、按钮挂到「操作日志」下。已整体迁到 **9320 段**。
2. **接口失败静默**：`applyGroup(null)` 把「请求失败」当「没有群」，卡片整块消失。已加 `groupError`
   状态 + 重试卡片——**失败也要留入口**，否则用户只会得出「这功能没做」的结论。

## 六、已知限制（不是 bug）

- 项目**没有 Redis**：WS 票据 / 发言频控 / 禁言缓存 / 广播都是进程内单例。
  **单实例部署功能完整**；上多实例前必须换 Redis，否则票会跨实例失效、频控阈值放大 N 倍、广播收不到。
- 归档任务每天跑一次（12 个月前消息分批 500 条迁到 `t_group_message_archive`），
  首跑后建议确认一次 `t_group_mention` 是否同步清空。
