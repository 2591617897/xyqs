## 一、总体结论

本次共确认 **18 项** 问题，其中 **严重 3 项、高危 5 项、中危 6 项、低危 4 项**。
最严重的三项是「身份头可伪造」「令牌密钥硬编码在仓库」「后台口令用 MD5」，任意一项单独存在，
整个权限体系都等于没有。三项均在本地实机复现成功（见附录 A 的原始请求与响应），现已全部修复并回归验证通过。

第二轮又把其中 5 项「建议下一步做」的残余风险真正落地（令牌吊销、服务端强制改密、C 端登录频控、
安全基线自检、加密备份，见第八节）。**当前 18 项中 15 项已修复，剩 3 项属于需要排期或产品决策的
（框架大版本升级、学生证照片私有化、UGC 正文明文），逐条列在第六节。**

## 二、问题清单（按风险排序）

### P0-1 微服务端口可被直连，请求头身份可伪造（严重）

**位置**
- `campus-common/.../security/SecurityAutoConfig.java`（C 端身份注入）
- `campus-admin/.../config/AdminAuthInterceptor.java`（后台身份注入）

**成因**
业务服务完全信任网关注入的 `X-User-Id` / `X-Admin-Id` 等请求头，但这些服务自身监听
`0.0.0.0:8101~8107`。只要能连上其中任一端口（同局域网、云安全组漏开、Docker 端口写成 `0.0.0.0`、
内网横向移动），加一行请求头就能以任意用户甚至超管身份调用接口，网关的 JWT 校验形同虚设。

**实机证据**
```
GET http://127.0.0.1:8102/user/me      Header: X-User-Id: 2114018677295706113
→ {"code":0,"data":{"nickname":"莫东海","studentNo":"****6644","realName":"莫**","verifyImg":"..."}}

GET http://127.0.0.1:8107/auth/info    Header: X-Admin-Id: 900000000000000001, X-Admin-Super: 1
→ {"code":0,"data":{"username":"admin","superFlag":true,"permissions":[...]}}
```

**影响**
越权读取全部用户资料、以任意身份发帖/私信/下单；后台侧等于超管全权限（封禁用户、看审核材料、改配置）。

**修复**
- C 端：身份**只从请求自带的 JWT 解出**，请求头仅作为「有没有身份」的信号。带有效令牌时用令牌内容覆盖请求头；
  没令牌却带 `X-User-Id` 一律 401 并打 WARN 日志（这是绕过网关的确定特征）。
- 后台：`AdminAuthInterceptor` 必须同时满足「Authorization 可验签 + `typ=admin` + subject 与 `X-Admin-Id` 一致」，
  且超管标记、数据权限范围、辖区**全部以令牌 claim 为准**，改头改不了权限。

### P0-2 令牌密钥硬编码在仓库，可自行签发任意身份令牌（严重）

**位置**：`campus-gateway/application.yml`、`campus-auth|user|goods|wall|post|message|admin/application.yml`、
`JwtService.java` / `AuthGlobalFilter.java` / `AdminJwtService.java` 的 `@Value` 默认值

**成因**：`campus.jwt.secret: campus-fun-jwt-secret-key-please-change-in-prod-2026` 这类默认值直接写在
配置文件与代码里，且注释写着 "please change in prod" 却从未强制。

**影响**：拿到仓库（或反编译 jar）的任何人都能离线签发 `sub=任意userId` 的合法令牌，
再配合 P0-1 直接接管账号；后台密钥同理，可直接伪造超管令牌。

**修复**
- 新增 `SecretStore`：密钥优先级 = 环境变量 → `~/.campus-secrets/<name>` → 首次随机生成并落盘（600 权限）。
- 配置文件与代码默认值全部清空；`CAMPUS_SECRET_STRICT=true` 时缺少环境变量直接**启动失败**（生产建议开启）。
- 令牌新增 `iss=campus-api` / `aud=campus-miniapp|campus-admin` / `typ=user|admin`，网关与业务侧双向校验，
  防止把 A 系统的令牌拿到 B 系统用。
- C 端令牌有效期 168h → 72h（小程序静默重登即可续期，安全收益更大）。

**注意**：密钥轮换后所有存量令牌失效，用户需重新登录一次（小程序侧无感，后台需重新登录）。

---

### P0-3 后台口令使用 MD5(明文+盐)，且全员共用同一个盐（严重）

**位置**：`campus-admin/.../config/AdminPasswordUtil.java`、`AuthAdminService`、`AdminUserService`、
`sql/migration-20261025-campus-admin-init.sql`

**成因**
- 摘要算法是 MD5：为「快速」设计，单张消费级显卡每秒可尝试数十亿次，8 位口令离线爆破基本等于明文。
- `salt` 列虽然存在，但初始化脚本里所有账号共用固定盐 `'c4m2p9s1'`，等于没有盐。
- 初始口令 `admin123`，且 `must_change_pwd` 只在后台弹窗提示，服务端不强制。

**影响**：数据库一旦泄露（SQL 注入、备份外泄、云盘误传），管理员口令立刻被还原，进而掌控整个后台。

**修复**
- 改为 **BCrypt（cost=12）**：自带随机盐、可调工作因子，单次校验约 200~400ms。
- **登录时自动升级**：老 MD5 记录校验通过后立即改写为 BCrypt，用户无感，无需停机刷库、无需强制全员改密。
- 口令策略：≥8 位、至少三类字符、弱口令黑名单、不得包含账号名（新建/改密/重置三条路径统一校验）。
- 账号不存在时也跑一次 BCrypt（`DUMMY_HASH`），避免用响应时间枚举账号。
- `password` 列扩到 `VARCHAR(100)`，`salt` 保留但新记录写空串（BCrypt 不需要外部盐）。

**验证**：用 `admin/admin123` 登录一次后，库中 `password` 前缀已从 32 位 hex 变为 `$2a$12$`，`salt` 为空。

### P1-1 个人敏感信息明文入库（高危）

**位置**：`t_user.phone / student_no / real_name / verify_img`、`t_goods_order.contact`、`t_user_verify_log.real_name / student_no`

**成因**：这些字段直接以明文存在 InnoDB 里，任何能读库的人（DBA、只读账号、备份文件、误传的 dump）
都能拿到全校学生的手机号、学号、真实姓名与校园卡照片地址，属于《个人信息保护法》意义上的敏感个人信息。

**修复**
- 新增 `DataCipher`（AES-256-GCM）：随机 12 字节 IV、128 位 tag，密文格式 `enc:v1:<base64>`。
- 新增 `EncryptedStringTypeHandler`：挂在实体字段上，业务代码读写都是明文，库里、备份里、从库里看到的都是密文。
  实体需 `@TableName(autoResultMap = true)`，否则只加密不解密（这个坑已在实机踩到并修复）。
- 加密列无法 `LIKE`/等值查询，新增**盲索引** `SearchHash`（HMAC-SHA256，密钥在应用侧，库泄露也无法反推）：
  - `t_user.student_no_hash` → 同校学号查重（`countStudentNoUsed` 改查它）
  - `t_user.phone_hash` → 后台按手机号精确搜索
- **不停机迁移**：无 `enc:v1:` 前缀的历史值读取时按明文返回，写回时自动加密；
  一次性脚本 `PlaintextMigrationRunner`（`CAMPUS_SECURITY_MIGRATE_PLAINTEXT=true`）把存量数据刷成密文并补齐盲索引。
- 后台列表只返回**脱敏手机号**，完整号码仅在详情页（有操作日志留痕）。

**验证**：写入手机号后库中为 `enc:v1:...`，接口读回为 `13800138000`；历史明文用户跑一次迁移后同样变为密文。

### P1-2 网关 CORS 允许任意来源并携带凭证（高危）

**位置**：`campus-gateway/.../GatewayApplication.java`

**成因**：`allowedOriginPatterns("*")` + `allowCredentials(true)`。这是浏览器规范中明确禁止的组合，
实际效果是「任意站点都能从受害者浏览器里带凭证调用后台接口」，属于典型的 CSRF 配置错误。

**修复**：改为来源白名单（`CORS_ALLOWED_ORIGINS`，默认本机 5173 + 线上管理台域名），
`allowCredentials(false)`（管理台用 Bearer 令牌，本来就不依赖 Cookie），并收窄允许的请求头。

**验证**：`Origin: https://evil.example.com` 不再返回 `Access-Control-Allow-Origin`；`http://localhost:5173` 正常返回。

### P1-3 数据库使用 root 账号、连接不加密（高危）

**位置**：各服务 `application.yml` 的 `datasource`

**成因**：`username: ${MYSQL_USER:root}`、`password: ${MYSQL_PWD:123456}`、`useSSL=false`。
应用账号拥有 DDL/GRANT/FILE 权限，一旦出现 SQL 注入即可删库、读 `mysql.user`、写服务器文件。

**修复（部分，需运维配合）**
- `sql/migration-20261026-security-hardening.sql` 提供最小权限账号脚本：`campus_app` 只授
  `SELECT/INSERT/UPDATE/DELETE`，另附只读报表账号 `campus_ro`。
- 连接串改为 `useSSL=${MYSQL_SSL:false}`、`allowPublicKeyRetrieval=${MYSQL_ALLOW_PUBLIC_KEY_RETRIEVAL:true}`，
  生产通过环境变量开启 TLS 并关闭公钥检索。
- 本地保留 `root/123456` 默认值仅为开发便利；**上线前必须改为 `campus_app` + 强口令**（见第七节清单）。

### P1-4 上传只校验扩展名，可落盘伪装文件（高危）

**位置**：`campus-user/.../UploadController.java`、`campus-admin/.../UploadController.java`

**成因**：只判断后缀在不在白名单里。把 `x.html` / `x.svg` 改名成 `x.png` 就能写进 `/uploads`，
而这个目录由 Nginx 直出；一旦 MIME 推断或浏览器行为不严，就是存储型 XSS / 钓鱼页托管。

**修复**：新增 `FileMagic` 校验真实文件头（JPEG/PNG/GIF/WEBP/MP4 的 magic bytes），
扩展名与内容必须同时匹配；网关与 Nginx 均加 `X-Content-Type-Options: nosniff`。

**验证**：内容为 `hello not an image` 的 `fake.png` 被 400 拒绝，真实 PNG 正常上传。

### P1-5 第三方凭据（腾讯位置服务 Key/SK）随代码提交（高危）

**位置**：`campus-auth/application.yml` 的 `campus.geo.qqmap-key` / `qqmap-sk`

**成因**：真实 Key/SK 以默认值形式写在配置里并已进入 Git 历史。

**影响**：他人可盗用配额（每日额度耗尽后定位能力整体失效），SK 泄露意味着可以伪造签名调用。

**修复**：配置默认值清空，改由环境变量 `QQMAP_KEY` / `QQMAP_SK` 注入；本地真实值移入
已被 `.gitignore` 忽略的 `application-local.yml`。
**建议**：该 Key/SK 已视为泄露，请到腾讯位置服务控制台**重置**后重新配置。

### P2-1 后台身份信息依赖请求头、令牌无吊销机制（中危）

**已修复（第二轮）**：`t_admin_user` 增加 `token_version`，签发令牌时写进 claim `tv`，
拦截器每次请求与库里的值比对；改密、重置密码、禁用、删除账号都会 `token_version+1`，
旧令牌下一次请求即 401。实测：改密后旧令牌立刻失效、新令牌正常，不必等 8 小时过期。
因为令牌会当场作废，`POST /auth/password` 改为返回**新令牌**，前端拿来自动替换，用户不会被自己踢下线。
未做本地缓存是刻意的 —— 这条查询只取主键上的三列，成本可忽略，而「改完密码立刻生效」是安全语义。

### P2-2 管理台令牌存 localStorage（中危）

`admin-web/src/utils/request.js` 把令牌放在 `localStorage`（永久存储，XSS 后长期复用）。
已改为 `sessionStorage`（关闭标签页即失效），并把允许的请求头收窄。根治方案是 httpOnly Cookie + CSRF Token，
需要网关与后台同时改造，列为后续项。

### P2-3 `/actuator` 前缀在网关整体放行（中危）

`WHITE_PREFIX` 里是 `"/actuator"`，一旦引入 actuator 依赖，`/actuator/env`、`/actuator/heapdump`
会向公网暴露配置与内存。已改为仅精确放行 `/actuator/health`。

### P2-4 后台用户列表返回完整手机号（中危）

运营页面其实只需要定位到人。已改为列表脱敏（`138****8000`），详情保留完整值并受操作日志约束。

### P2-5 依赖版本滞后（中危）

`Spring Boot 3.2.5` / `Spring Cloud 2023.0.1` / `Gateway 4.1.2`（2024 年上半年版本），
该分支的社区维护已结束，后续披露的 CVE 不会再有补丁。本次**未擅自升级**（跨小版本会牵动
Spring Cloud Alibaba 与 Nacos 客户端，需完整回归），建议按计划升级到 Spring Boot 3.5.x + Spring Cloud 2025.0.x。
管理台前端依赖（axios 1.7 / vite 5.4 / element-plus 2.8）暂无高危告警，建议随大版本一并更新。

### P2-6 登录风控只覆盖后台（中危）

**已修复（第二轮）**：`campus-auth` 增加 `LoginRateLimiter`，按 **IP**（默认 30 次/分钟）与
**openid**（默认 10 次/分钟）各做一条滑动窗口。IP 维度在调 `code2Session` **之前**就拦
（保护微信日调用配额被刷爆），openid 维度拿到身份后再拦；超限返回 `429` 并打 warn 日志。
阈值可用 `CAMPUS_AUTH_LOGIN_*` 调整。计数在进程内存里，多实例部署时实际阈值会被放大 ——
需要横向扩容时把 `hit()` 换成 Redis 的 `ZADD/ZREMRANGEBYSCORE` 即可，接口签名不用改。

### P3-1 私信与 UGC 正文明文存储（低危）

属于业务必要数据，且已过内容安全审核；不在本次加密范围（加密会破坏全文检索与后台审核效率）。

### P3-2 学生证照片走公网静态目录（低危）

`verify_img` 存的是可直接访问的 URL，知道路径即可查看。建议后续迁移到对象存储私有桶 + 短时效签名 URL。

### P3-3 数据库备份未加密（低危）

**已修复（第二轮）**：新增 `scripts/backup-db.sh`，`mysqldump` 直连管道到
`openssl enc -aes-256-cbc -pbkdf2 -iter 200000`，明文只存在于 `mktemp` 临时文件里，
`trap` 保证失败也删除；未设置 `CAMPUS_BACKUP_PASSPHRASE` 时**拒绝执行**（不允许产出明文备份）；
加密文件 `chmod 600`，默认保留 7 天。口令必须与备份分开保管（密码管理器 / KMS）。

### P3-4 无统一的安全基线自检（低危）

**已修复（第二轮）**：新增 `scripts/security-baseline-check.js`（可直接进 CI），
把七类「已修好的问题」变成会失败的断言：硬编码密钥、敏感字段加密 TypeHandler、
身份只来自令牌、网关放行名单、CORS、上传魔数校验、口令哈希与吊销。
实现上**必须先剔注释再匹配**——否则加固说明里引用的旧写法会被当成漏洞本身（第一版就踩了这个坑）。
当前结果：`失败 0 项，告警 1 项`（告警项是 `AdminPasswordUtil` 保留 `md5Hex` 用于兼容旧哈希升级，属预期）。

## 五、上线步骤（务必按顺序）

1. **备份数据库**（`mysqldump`），并单独妥善保存 `CAMPUS_DATA_KEY`。
2. 执行 `backend/sql/migration-20261026-security-hardening.sql`（加列、扩列、建索引、建低权限账号）。
3. 生成三个密钥并注入环境变量（**所有服务与网关必须一致**）：
   ```bash
   openssl rand -base64 32   # JWT_SECRET
   openssl rand -base64 32   # ADMIN_JWT_SECRET
   openssl rand -base64 32   # CAMPUS_DATA_KEY（丢失=密文永久解不开）
   ```
   生产同时设置 `CAMPUS_SECRET_STRICT=true`。
4. 将 `MYSQL_USER/MYSQL_PWD` 换成 `campus_app` + 强口令；内网开启 `MYSQL_SSL=true`；把
   `CORS_ALLOWED_ORIGINS` 换成真实管理台域名。
5. **第二轮追加一步**：执行 `backend/sql/migration-20261026-admin-token-revoke.sql`（幂等，可重复跑），
   给 `t_admin_user` 加 `token_version`；然后重启 `campus-admin`（它启动时会 select 该列）。
6. 首次启动时设置 `CAMPUS_SECURITY_MIGRATE_PLAINTEXT=true`（user 与 goods 各启动一次），
   确认日志出现「迁移完成，共更新 N 行」后**立即关闭**该开关并重启。
7. 去腾讯位置服务控制台**重置**已泄露的 Key/SK，重新配置 `QQMAP_KEY` / `QQMAP_SK`。
8. 用 `admin` 登录一次（会自动把初始口令升级为 BCrypt），**必须**在弹窗里改成一个强口令；
   改完前端会自动换用新令牌，旧令牌立即失效。`auditor` 同理（本地已重置为
   `Campus@2026#Audit` 并且同样要求首次登录改密）。
9. 配置 `CAMPUS_BACKUP_PASSPHRASE` 并把 `scripts/backup-db.sh` 加进 crontab（每日一次，保留 7 天）。
10. 服务器侧：`8101~8107` 只监听内网或 `127.0.0.1`（`server.address`），云安全组不对外开放。
11. 回归：小程序登录、发帖、私信、上传、后台登录与用户列表；
    另跑 `node scripts/security-baseline-check.js`（应 `失败 0 项`）。

## 六、残余风险与后续建议

1. **数据库仍用 root（本地）** —— 本地开发便利，生产必须切 `campus_app`（脚本第四节已给 GRANT），
   这是当前最大的剩余风险。
2. **框架版本待升级** —— Spring Boot 3.2.x 已停止维护，建议排期升级到 3.5.x（需连带 Spring Cloud / Nacos 客户端回归）。
3. **学生证照片公网可达** —— 仍是静态目录直出，建议对象存储私有桶 + 短时效签名 URL；
   改造会牵动上传接口与后台两个列表页，收益有限，故未在本轮动。
4. **私信 / UGC 正文明文** —— 有意保留（加密会破坏全文检索与审核效率），靠磁盘加密 + 最小权限兜底。
5. **C 端频控计数在单机内存** —— 多实例部署时阈值会按实例数放大，扩容前需换 Redis 实现。
6. **登录风控只做到「限流」** —— 还没有异地登录 / 新设备提醒，需要设备指纹与消息通道，属于产品级需求。
6. **缺乏统一的安全基线检查** —— 建议 CI 增加密钥扫描（`git secrets` 或自研正则），
   禁止 `secret: 字面量` 再次进入仓库。

## 八、第二轮加固（残余风险收口）

第一轮修完 P0/P1 之后，剩下 5 项「建议下一步做」的事。这一轮把它们全部落地，
目标很明确：**让「被泄露的令牌 / 未改的初始密码 / 被刷的登录接口 / 被回退的加固」都不会悄悄发生**。

### 8.1 令牌吊销（`token_version`）

| 位置 | 改动 |
| --- | --- |
| `sql/migration-20261026-admin-token-revoke.sql` | 新增 `t_admin_user.token_version`，用 `information_schema` 判断，**幂等** |
| `AdminUserMapper` | `selectAuthState`（只查 status / token_version / must_change_pwd 三列）+ `bumpTokenVersion`（SQL 自增，避免并发覆盖） |
| `AdminJwtService` | 令牌增加 claim `tv` |
| `AdminAuthInterceptor` | 每次请求比对 `tv` 与库里值，不一致 → 401「登录状态已失效」 |
| `AdminUserService` | `revokeTokens()`；改密 / 改状态 / 重置口令 / 删除时调用 |
| `AuthAdminService` | 登录按当前版本签发；改密后 `+1` 并返回**新令牌** |
| `admin-web/layout/Navbar.vue` | 改密成功后替换本地令牌，不再强制重新登录 |

### 8.2 服务端强制改密

`must_change_pwd=1` 的账号，只放行 `/auth/info`、`/auth/password`、`/auth/logout`、`/auth/menus`，
其余一律 `403 请先修改初始密码后再使用后台`。以前这一步只靠前端弹窗，绕过前端直接调接口就能
拿初始口令长期使用。开关 `campus.admin.force-password-change`（默认 true，只给本地演示留逃生阀）。

### 8.3 C 端登录频控

`campus-auth/security/LoginRateLimiter`：IP 30 次/分钟、openid 10 次/分钟，滑动窗口，
超限 `429` + warn 日志；IP 那层在 `code2Session` 之前，顺带保护微信日调用配额。
`BizException` 新增 `tooManyRequests()`（code 429）。

### 8.4 安全基线自检

`scripts/security-baseline-check.js`：七类断言（硬编码密钥 / 敏感字段 TypeHandler / 身份只来自令牌 /
网关放行名单 / CORS / 上传魔数 / 口令哈希与吊销），纯静态扫描，可直接进 CI。

### 8.5 加密备份

`scripts/backup-db.sh`：未设 `CAMPUS_BACKUP_PASSPHRASE` 直接拒绝执行；`openssl enc -aes-256-cbc
-pbkdf2 -iter 200000`；明文落在 `mktemp`，`trap` 兜底删除；加密件 `chmod 600`；默认保留 7 天。

### 8.7 这一轮踩到的两个坑

1. **静态扫描必须先剔注释**。加固说明里写着「以前是 `allowedOriginPatterns("*")`」，
   第一版脚本把这句注释当成了真漏洞，报了一堆假阳性。现在统一 `stripComments()` 再匹配。
2. **「改密即失效」会把人锁在门外**。只加 `token_version` 而不返回新令牌，
   用户改完密码自己就被踢了（前端还以为是密码错误）。所以 `/auth/password` 改成返回新令牌，
   前端替换存储 —— 这两件事必须成对做。

## 附录 B：构建环境的一个坑（顺带修复）

排查过程中发现 `campus-goods` / `campus-post` 启动报 `NoClassDefFoundError: LikeMapper`。
根因不在代码：IDE（redhat.java 语言服务器）在后台做增量编译，把多模块工程的
「未解析类型」也编译成了 class 文件写进 `target/classes`，覆盖了 Maven 的正常产物
（`javap` 可见 `Unresolved compilation problems: LikeMapper cannot be resolved`）。

处理：新增 `.vscode/settings.json` 关闭 `java.autobuild.enabled`，构建统一交给
`mvn -DskipTests clean install`。这不是安全项，但会让人误判为「改坏了代码」，一并记录。
